# Existing dashboard direction

This document records the visual direction already present in the project. It is documentation, not a redesign brief.

- Identity: quarterly performance reporting for Institut Teknologi PLN, using the existing IT PLN logo and institutional dashboard context.
- Visual language: restrained light dashboard with navy text, blue action accents, pale blue surfaces, and status colors reserved for workflow states.
- Typography: compact sans-serif sizing and dense information hierarchy suited to reviewing reports, targets, and realization data.
- Composition: practical dashboard grids, timelines, charts, forms, and modal workflows rather than marketing sections.
- Dials: ENERGY 1 / RHYTHM 2 / MOTION 3. User-authorized motion override retains the institutional layout and palette.
- Motion purpose: GSAP sequences the welcome, deadline, quick access, and summary metrics to orient staff; document status and chart bars reveal together when their sections enter the native document viewport. Admin summaries share this vocabulary. Brief navigation and dialog entrances identify context changes without delaying clicks, saves, dismissal, or focus.
- Motion boundaries: no loops, pinning, scroll hijacking, animated numbers, or blanket element reveals. Content is visible by default; below-fold animation initializes only on entry. Scoped contexts and media queries revert on navigation, unmount, reduced-motion changes, and print media. Reduced motion is static. Existing card hover transforms remain CSS-owned; GSAP moves their parent instead.
- Admin workflow: switch roles below the Andi Rahman profile; no authentication is implemented. Monitoring charts derive from stored documents and active filters. Verification supports indicator notes, revision, approval, and dated review history. Archives reuse the document print preview.
- Deadlines: configured per year and quarter (or annual), using Asia/Jakarta (WIB, UTC+07:00), independent of browser timezone. New submissions are allowed through 23:59:59.999 on the selected date and blocked from the next millisecond. Closed periods block immediately; reopening does not extend an expired deadline. Invalid dates fail closed. Drafts and requested revisions remain available. Quarterly drafting does not require annual approval.
- Draft reliability: quarterly content and unit metadata autosave in browser storage; annual criteria already autosave. Saved drafts do not block navigation. Unsaved revision edits, review notes, period settings, and storage failures block internal navigation/role changes and warn before unloading. Save or revert those edits before leaving.
- Regression validation: Node 22.18+ or Node 24 supports `npm.cmd test` without additional packages. Twenty cases cover Jakarta boundaries, closed/reopened periods, invalid dates, revision exceptions, review eligibility, and revision history preservation.
- Print reliability: print-only CSS uses page margins, repeating table headers, visible overflow and break avoidance for rows/signatures. Native headless Chrome generated four component-fixture PDFs: 100-target annual (5 pages), quarterly (6), annual with an oversized target (13), and quarterly with an oversized target (19). PDF text extraction found all 100 target markers and all 1,800 oversized-row tokens, repeated table headers on table pages, and signatures on the final page. The fixture did not reproduce the dashboard ancestor typography selectors, so these counts are not full-app acceptance evidence. The first page contained metadata without the table; full-app pagination and visual overlap inspection remain outstanding. CDP printToPDF is unavailable in the shared browser.
- Browser evidence: quarterly draft retained across role changes and reload; 390px form viewport had no horizontal overflow. Test localStorage was restored byte-for-byte. This is targeted evidence, not a claim that every control or accessibility pairing was re-audited.
- Persistence: browser-local `quarterly-reporting-v1`, with migration for older criteria and absent deadline settings. Unreadable storage is preserved rather than overwritten. Use one browser tab for editing; there is no backend or multi-user synchronization. Initial documents are demonstration data.
- Development: restore with `corepack pnpm install --frozen-lockfile`; launch the VS Code Dev server task or `npm.cmd run dev -- --host 127.0.0.1`. Validate with `node node_modules\\typescript\\bin\\tsc --noEmit` and `npm.cmd run build`.
- Accessibility: navigation retains accessible names when tablet labels are hidden. Dialog Escape handling survives print focus changes and applies only to the topmost dialog. Controls retain visible focus, reduced-motion support, and scrollable mobile navigation.
- Dashboard accuracy: deadline and submission status come from configured periods; recent documents come from stored records. Draft messaging does not invent save timestamps.
- Preservation rule: keep the current layout, palette, content structure, and interaction model unless the user explicitly asks for a visual change.
